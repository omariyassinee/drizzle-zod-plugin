# Declarative Error Mapping Plan: `refineSchema(schema, callback?, errorMap?)`

## Overview

This plan specifies the design and implementation of declarative, schema-aware error mapping in `@vacuus/drizzle-validators` using a single unified entry point:

```ts
refineSchema(schema, errorMap)
refineSchema(schema, callback, errorMap?)
```

### Core Design Invariants
1. **Pure Zod Return Type:** `refineSchema` continues to return a standard `z.ZodObject` instance via `rebuildZodObject`. Native Zod composition methods (`.pick()`, `.omit()`, `.partial()`, `.extend()`) work without losing custom methods or breaking chains.
2. **Left-to-Right TypeScript Inference:** Placing `callback` (2nd arg) before `errorMap` (3rd arg) allows TypeScript to infer newly added fields (e.g., `confirmPassword`) and replaced field types before type-checking the keys of `errorMap`.
3. **Inline Precedence Over Error Map:** Explicit inline errors defined inside `callback` (e.g., `fields.age.min(18, { error: "..." })` or `fields.email.setError("...")`) always take priority over fallback messages in `errorMap`.
4. **C1 Immutability Guarantee:** Applying an `errorMap` clones the targeted field definitions and check objects (`cloneSchemaWithDef`, `cloneZodCheck`) so the base Drizzle schema and sibling refinements are never mutated.
5. **Zero Bundle Bloat:** Everything operates on Zod 4's existing `_zod.def` runtime structure without importing Zod locales or the monolithic `z` namespace.

## 1. API Surface & Usage Patterns

### Pattern 1: Error-Only Refinement (2 Arguments)
When the database column constraints generated by Drizzle (`notNull`, `varchar(255)`, `integer`, `uuid`, `pgEnum`) are already sufficient and only custom error messages are needed:

```ts
import { insertSchema, refineSchema } from "virtual:drizzle-validators/usersTable";

export const userInsertSchema = refineSchema(insertSchema, {
  // 1. String shorthand: overrides all errors on this field
  name: "Please provide a valid name",

  // 2. Granular object: maps specific failure modes on this field
  email: {
    required: "Email address is required",
    null: "Email cannot be null",
    invalid_type: "Email must be a text string",
    max: "Email cannot exceed 255 characters",
  },

  // 3. Dynamic error functions receive the Zod 4 issue object
  age: {
    invalid_type: "Age must be a number",
    int: "Age must be a whole number",
    min: (issue) => `Minimum allowed age is ${issue.minimum}`,
    max: "Age value is out of range",
  },
});
```

### Pattern 2: Rule Refinement + Error Map (3 Arguments)
When extending validation rules, swapping formats with `.as()`, or adding virtual form fields alongside a centralized error dictionary:

```ts
import { insertSchema, refineSchema } from "virtual:drizzle-validators/usersTable";
import { email, string } from "zod";

export const registerUserSchema = refineSchema(
  insertSchema,
  (fields) => ({
    email: fields.email.as(email()),
    // Inline error on .min(18) takes precedence over errorMap.age.min
    age: fields.age.min(18, { error: "You must be at least 18 to register" }),
    // New virtual field added to the schema
    confirmPassword: string().min(8),
  }),
  {
    email: {
      required: "Email is required",
      format: "Please enter a valid email address",
      max: "Email cannot exceed 255 characters", // Styles inherited varchar(255) check
    },
    age: {
      required: "Age is required",
      invalid_type: "Age must be a valid number",
      min: "Fallback min age error", // Ignored because inline error on .min(18) wins
    },
    // Autocompleted because `confirmPassword` was returned by the 2nd argument!
    confirmPassword: {
      required: "Please confirm your password",
      min: "Password confirmation must be at least 8 characters",
    },
  },
);
```

### Pattern 3: Field-Level `.setError()` / `.withError()` Parity
For consistency, `fields.<column>.setError(...)` and `fields.<column>.withError(...)` also accept a `FieldErrorMap` object in addition to a `string` or function:

```ts
export const loginSchema = refineSchema(insertSchema, (fields) => ({
  email: fields.email.as(email()).setError({
    required: "Email is required",
    format: "Invalid email format",
  }),
}));
```

## 2. Type System Design (`src/refine.ts`)

### 2.1 Error Map Types
Instead of complex check-prediction types, every field in `SchemaErrorMap<TShape>` accepts `FieldErrorInput`—either a catch-all `ErrorMessage` or a structured `FieldErrorMap` dictionary covering all Zod 4 validation failure modes:

```ts
import type { STRING_FORMAT_NAMES } from "./constants";

export type StringFormat = (typeof STRING_FORMAT_NAMES)[number];

/** Static string or dynamic callback receiving the raw Zod 4 issue payload */
export type ErrorMessage = string | ((issue: Record<string, any>) => string);

/**
 * Granular error dictionary for a schema field.
 */
export type FieldErrorMap = {
	/** Catch-all fallback for any unmapped error on this field */
	default?: ErrorMessage;

	// --- Core Type & Presence ---
	/** Triggered when input is `undefined` on a required field */
	required?: ErrorMessage;
	/** Triggered when input is `null` on a non-nullable field */
	null?: ErrorMessage;
	/** Triggered when input has the wrong primitive/object type */
	invalid_type?: ErrorMessage;
	/** Triggered when input fails a `z.enum()` or `z.literal()` check */
	invalid_value?: ErrorMessage;

	// --- Size, Length & Numeric Bounds ---
	/** Triggered on `.min()`, `.gt()`, `.gte()`, or `too_small` issues */
	min?: ErrorMessage;
	/** Triggered on `.max()`, `.lt()`, `.lte()`, or `too_big` issues */
	max?: ErrorMessage;
	/** Triggered on `.length()` exact-length checks */
	length?: ErrorMessage;
	/** Triggered on `.int()` or `z.int()` safe-integer checks */
	int?: ErrorMessage;
	/** Triggered on `.multipleOf()` checks */
	multiple_of?: ErrorMessage;

	// --- String Formats & Patterns ---
	/** Generic fallback for any string format check (`email`, `uuid`, `url`, `regex`, etc.) */
	format?: ErrorMessage;
	/** Triggered specifically on `.regex()` checks */
	regex?: ErrorMessage;
	/** Triggered specifically on `.startsWith()` checks */
	starts_with?: ErrorMessage;
	/** Triggered specifically on `.endsWith()` checks */
	ends_with?: ErrorMessage;
	/** Triggered specifically on `.includes()` checks */
	includes?: ErrorMessage;
	/** Triggered on `.refine()` / custom checks lacking an inline error */
	custom?: ErrorMessage;
} & {
	/** Specific format overrides (`email`, `uuid`, `url`, `ipv4`, etc.) */
	[K in StringFormat]?: ErrorMessage;
};

export type FieldErrorInput = ErrorMessage | FieldErrorMap;
```

### 2.2 Schema Shape & Overload Types
To ensure the 3rd argument (`errorMap`) knows about fields modified or added in the 2nd argument (`refinementFn`), extract the merged shape computation into a reusable type alias `MergedRefinedShape<TShape, R>`:

```ts
export type MergedRefinedShape<
	TShape extends Record<string, z.ZodTypeAny>,
	R extends RefinementCallbackResult<TShape>,
> = Omit<TShape, keyof R> & {
	[K in keyof R]: K extends keyof TShape
		? ResolveRefinedField<TShape[K], R[K]>
		: R[K] extends z.ZodTypeAny
			? R[K]
			: never;
};

export type SchemaErrorMap<TShape extends Record<string, z.ZodTypeAny>> = {
	[K in keyof TShape]?: FieldErrorInput;
};
```

### 2.3 Function Overloads for `refineSchema`
```ts
// Overload 1: (schema, errorMap) — Declarative errors only
export function refineSchema<T extends z.ZodObject<any>>(
	baseSchema: T,
	errorMap: SchemaErrorMap<T["shape"]>,
): z.ZodObject<T["shape"]>;

// Overload 2: (schema, callback, errorMap?) — Rules + optional declarative errors
export function refineSchema<
	T extends z.ZodObject<any>,
	R extends RefinementCallbackResult<T["shape"]>,
>(
	baseSchema: T,
	refinementFn: (fields: RefinableShape<T["shape"]>) => R,
	errorMap?: SchemaErrorMap<MergedRefinedShape<T["shape"], R>>,
): z.ZodObject<MergedRefinedShape<T["shape"], R>>;
```

## 3. Runtime Dispatch & Zod 4 Internals

In Zod 4 (`^4.4.3`), validation errors originate from two places on a field's unwrapped core schema and its wrappers:

1. **Core Schema Definition (`def.error`):**
   Handles root-level issues where no child check in `def.checks` is responsible, or where the schema itself is a format/choice type:
   * `issue.code === "invalid_type"`:
     * `issue.input === undefined` $\rightarrow$ maps to `map.required ?? map.invalid_type ?? map.default`
     * `issue.input === null` $\rightarrow$ maps to `map.null ?? map.invalid_type ?? map.default`
     * Any other input $\rightarrow$ maps to `map.invalid_type ?? map.default`
   * `issue.code === "invalid_value"` (`z.enum`, `z.literal`) $\rightarrow$ maps to `map.invalid_value ?? map.default`
   * `issue.code === "invalid_format"` (top-level `z.email()`, `z.uuid()`, `z.url()`, `z.iso.*()`) $\rightarrow$ maps to `map[issue.format ?? def.format] ?? map.format ?? map.default`
   * `issue.code === "too_small"` $\rightarrow$ maps to `map.min ?? map.default`
   * `issue.code === "too_big"` $\rightarrow$ maps to `map.max ?? map.default`

2. **Attached Checks Array (`def.checks`):**
   Each check object in `def.checks` has `_zod.def.check` and its own `_zod.def.error` function. The mapping from `_zod.def.check` to `FieldErrorMap` is:

| `checkDef.check` | Sub-discriminator (`checkDef.format`) | Lookup Priority in `FieldErrorMap` |
| :--- | :--- | :--- |
| `"min_length"` | — | `map.min ?? map.default` |
| `"greater_than"` | — | `map.min ?? map.default` |
| `"max_length"` | — | `map.max ?? map.default` |
| `"less_than"` | — | `map.max ?? map.default` |
| `"length_equals"` | — | `map.length ?? map.default` |
| `"multiple_of"` | — | `map.multiple_of ?? map.default` |
| `"number_format"` | `"safeint"` | `map.int ?? map.default` |
| `"string_format"` | `"regex"`, `"starts_with"`, `"ends_with"`, `"includes"`, `"email"`, `"uuid"`, etc. | `map[checkDef.format] ?? map.format ?? map.default` |
| `"custom"` | — | `map.custom ?? map.default` |

## 4. Precedence & Non-Contamination Rules

When both `callback` (2nd arg) and `errorMap` (3rd arg) touch the same field, **inline errors defined in `callback` must win**.

### 4.1 Four-Tier Priority Hierarchy
For any validation failure on a field:
1. **Tier 1 (Highest):** Explicit inline error set in `callback` (e.g., `fields.age.min(18, { error: "Inline" })`, `fields.email.as(z.email({ error: "Inline" }))`, or `fields.name.setError("Inline")`).
2. **Tier 2:** Specific check/issue key in `errorMap` (e.g., `errorMap.age.min`, `errorMap.email.required`, `errorMap.email.email`).
3. **Tier 3:** Field-level catch-all in `errorMap` (`errorMap.age.default` or `errorMap: { age: "Catch-all" }`).
4. **Tier 4 (Lowest):** Zod 4's built-in default error message.

### 4.2 How Inline Precedence Works at Runtime
Generated Drizzle schemas emit bare builders (`z.string().max(255)`, `z.int().gte(...).lte(...)`) where `def.error` and `checkDef.error` are `undefined`.

Therefore, after `callback` runs:
* **On Checks (`def.checks`):** If `typeof checkDef.error === "function"` is already present on a check, that check was given an explicit inline error in `callback`. When applying `errorMap` (`preserveInline = true`), `cloneZodCheck` leaves `checkDef.error` untouched.
* **On Core Schema (`def.error`):** If `typeof def.error === "function"` is already present (`existingErrorFn`):
  * If the core schema was explicitly stamped by `.setError()` in `callback`, `existingErrorFn` wins unconditionally.
  * If the core schema is a root format builder like `z.email({ error: "Inline email error" })` (`typeof def.format === "string"`), `existingErrorFn` was provided for the format check—so it takes precedence when `issue.code === "invalid_format"`, while still allowing `errorMap.email.required` or `errorMap.email.null` to customize missing/null inputs!
  * If the core schema is a non-format builder like `z.string({ error: "Inline string error" })`, `existingErrorFn` takes precedence on `invalid_type` issues.

## 5. Step-by-Step File Changes

### Step 1: Update `src/zod-compat.ts`
Update `cloneZodCheck` to accept an error function `(issue: Record<string, any>) => string | undefined` (in addition to `string`) and a `preserveInline` flag so existing check-level inline errors aren't overwritten when applying `errorMap`:

```ts
export type ZodErrorOverride =
	| string
	| ((issue: Record<string, any>) => string | undefined);

export function cloneZodCheck(
	check: unknown,
	errorOverride?: ZodErrorOverride,
	preserveInline = false,
): z.ZodTypeAny {
	const checkDef = getZodDef(check);
	if (!checkDef) {
		throw new DrizzleValidatorsError(
			"Cannot clone a malformed Zod check without a definition.",
		);
	}
	const nextDef = { ...checkDef };
	const hasInlineError = typeof checkDef.error === "function";

	if (errorOverride !== undefined && !(preserveInline && hasInlineError)) {
		nextDef.error =
			typeof errorOverride === "function"
				? errorOverride
				: () => errorOverride;
	}
	return new (getZodConstructor(check, "check cloning"))(nextDef);
}
```

### Step 2: Update `src/refine.ts`
1. **Add a symbol to track explicit `.setError()` calls** so `errorMap` never overwrites a field that called `.setError()` in `callback`:

2. **Implement `evalErrorMessage` and `resolveCheckError`:**
   ```ts
   function evalErrorMessage(
   	msg: ErrorMessage | undefined,
   	issue: Record<string, any>,
   ): string | undefined {
   	if (msg === undefined) return undefined;
   	return typeof msg === "function" ? msg(issue) : msg;
   }

   function resolveCheckError(
   	checkDef: Record<string, any>,
   	map: FieldErrorMap,
   ): ErrorMessage | undefined {
   	switch (checkDef.check) {
   		case "min_length":
   		case "greater_than":
   			return map.min ?? map.default;
   		case "max_length":
   		case "less_than":
   			return map.max ?? map.default;
   		case "length_equals":
   			return map.length ?? map.default;
   		case "multiple_of":
   			return map.multiple_of ?? map.default;
   		case "number_format":
   			return map.int ?? map.default;
   		case "string_format": {
   			const fmt = String(checkDef.format ?? "");
   			const specific = (map as Record<string, ErrorMessage | undefined>)[fmt];
   			return specific ?? map.format ?? map.default;
   		}
   		case "custom":
   			return map.custom ?? map.default;
   		default:
   			return map.default;
   	}
   }
   ```

3. **Upgrade `setErrorOnField(field, errorInput, preserveInline = false)`:**
   ```ts
   function setErrorOnField(
   	field: z.ZodTypeAny,
   	errorInput: FieldErrorInput,
   	preserveInline = false,
   ): z.ZodTypeAny {
   	const def = getZodDef(field);
   	if (!def) {
   		throw new DrizzleValidatorsError(
   			"Cannot set an error on a schema without a Zod definition.",
   		);
   	}

   	// If this node was already explicitly styled via .setError() in the callback,
   	// and we are now applying the 3rd-arg errorMap (preserveInline = true), keep it intact.
   	if (
   		preserveInline &&
   		Reflect.get(field as object, EXPLICIT_SET_ERROR_BRAND) === true
   	) {
   		return field;
   	}

   	// Case 1: Catch-all string or function
   	if (typeof errorInput === "string" || typeof errorInput === "function") {
   		const checks = Array.isArray(def.checks)
   			? def.checks.map((check: unknown) =>
   					cloneZodCheck(check, errorInput, preserveInline),
   				)
   			: undefined;
   		const innerType = def.innerType
   			? setErrorOnField(def.innerType, errorInput, preserveInline)
   			: undefined;
   		const element = def.element
   			? setErrorOnField(def.element, errorInput, preserveInline)
   			: undefined;

   		const hasInlineDefError = typeof def.error === "function";
   		const nextError =
   			preserveInline && hasInlineDefError
   				? def.error
   				: typeof errorInput === "function"
   					? errorInput
   					: () => errorInput;

   		const cloned = cloneSchemaWithDef(
   			field,
   			{
   				error: nextError,
   				...(checks ? { checks } : {}),
   				...(innerType ? { innerType } : {}),
   				...(element ? { element } : {}),
   			},
   			"error override",
   		);
   		if (!preserveInline) {
   			Object.defineProperty(cloned, EXPLICIT_SET_ERROR_BRAND, {
   				value: true,
   				enumerable: false,
   				configurable: true,
   			});
   		}
   		return cloned;
   	}

   	// Case 2: Granular FieldErrorMap object
   	const map = errorInput;
   	const existingDefError =
   		typeof def.error === "function" ? def.error : undefined;
   	const isRootFormatSchema = typeof def.format === "string";

   	const checks = Array.isArray(def.checks)
   		? def.checks.map((check: unknown) => {
   				const checkDef = getZodDef(check);
   				const matched = checkDef
   					? resolveCheckError(checkDef, map)
   					: undefined;
   				return cloneZodCheck(check, matched, preserveInline);
   			})
   		: undefined;

   	const innerType = def.innerType
   		? setErrorOnField(def.innerType, errorInput, preserveInline)
   		: undefined;

   	const dispatchCoreError = (
   		issue: Record<string, any>,
   	): string | undefined => {
   		// If an inline error exists on the core def:
   		// - On root format schemas (e.g. z.email({ error: "..." })), it wins for invalid_format
   		// - On non-format schemas (e.g. z.string({ error: "..." })), it wins for invalid_type
   		if (preserveInline && existingDefError) {
   			if (isRootFormatSchema && issue.code === "invalid_format") {
   				return existingDefError(issue);
   			}
   			if (!isRootFormatSchema) {
   				return existingDefError(issue);
   			}
   		}

   		if (issue.code === "invalid_type") {
   			if (issue.input === undefined) {
   				const m = map.required ?? map.invalid_type ?? map.default;
   				if (m !== undefined) return evalErrorMessage(m, issue);
   			} else if (issue.input === null) {
   				const m = map.null ?? map.invalid_type ?? map.default;
   				if (m !== undefined) return evalErrorMessage(m, issue);
   			} else {
   				const m = map.invalid_type ?? map.default;
   				if (m !== undefined) return evalErrorMessage(m, issue);
   			}
   		} else if (issue.code === "invalid_value") {
   			const m = map.invalid_value ?? map.default;
   			if (m !== undefined) return evalErrorMessage(m, issue);
   		} else if (issue.code === "invalid_format") {
   			const fmt = String(issue.format ?? def.format ?? "");
   			const specific = (map as Record<string, ErrorMessage | undefined>)[fmt];
   			const m = specific ?? map.format ?? map.default;
   			if (m !== undefined) return evalErrorMessage(m, issue);
   		} else if (issue.code === "too_small") {
   			const m = map.min ?? map.default;
   			if (m !== undefined) return evalErrorMessage(m, issue);
   		} else if (issue.code === "too_big") {
   			const m = map.max ?? map.default;
   			if (m !== undefined) return evalErrorMessage(m, issue);
   		} else if (map.default !== undefined) {
   			return evalErrorMessage(map.default, issue);
   		}

   		return existingDefError ? existingDefError(issue) : undefined;
   	};

   	const cloned = cloneSchemaWithDef(
   		field,
   		{
   			error: dispatchCoreError,
   			...(checks ? { checks } : {}),
   			...(innerType ? { innerType } : {}),
   		},
   		"error override",
   	);
   	if (!preserveInline) {
   		Object.defineProperty(cloned, EXPLICIT_SET_ERROR_BRAND, {
   			value: true,
   			enumerable: false,
   			configurable: true,
   		});
   	}
   	return cloned;
   }
   ```

4. **Update `refineSchema` runtime body to handle `(schema, errorMap)` and `(schema, callback, errorMap?)`:**
   ```ts
   export function refineSchema<
   	T extends z.ZodObject<any>,
   	R extends RefinementCallbackResult<T["shape"]> = {},
   >(
   	baseSchema: T,
   	refinementOrErrorMap:
   		| ((fields: RefinableShape<T["shape"]>) => R)
   		| SchemaErrorMap<T["shape"]>,
   	maybeErrorMap?: SchemaErrorMap<MergedRefinedShape<T["shape"], R>>,
   ): any {
   	if (
   		typeof refinementOrErrorMap !== "function" &&
   		(!refinementOrErrorMap || typeof refinementOrErrorMap !== "object")
   	) {
   		throw new DrizzleValidatorsError(
   			"refineSchema expects a refinement callback function or an error map object as its second argument.",
   		);
   	}

   	const nextShape: Record<string, z.ZodTypeAny> = { ...baseSchema.shape };

   	// Step 1: Run refinement callback if 2nd argument is a function
   	if (typeof refinementOrErrorMap === "function") {
   		const result = refinementOrErrorMap(
   			createLazyShapeProxy(baseSchema.shape) as RefinableShape<T["shape"]>,
   		);
   		if (!result || typeof result !== "object") {
   			throw new DrizzleValidatorsError(
   				"refineSchema callback must return an object mapping field names to schemas.",
   			);
   		}
   		for (const [key, value] of Object.entries(result)) {
   			if (value === undefined) continue;
   			const schema = unwrapProxy(value);
   			if (!isZodSchema(schema)) {
   				throw new DrizzleValidatorsError(
   					`Invalid refinement for field "${key}": expected a Zod schema instance, received ${typeof value}.`,
   				);
   			}
   			nextShape[key] = schema;
   		}
   	}

   	// Step 2: Apply declarative errorMap (either 2nd arg object or 3rd arg object)
   	const errorMap =
   		typeof refinementOrErrorMap === "function"
   			? maybeErrorMap
   			: refinementOrErrorMap;

   	if (errorMap !== undefined) {
   		if (!errorMap || typeof errorMap !== "object" || Array.isArray(errorMap)) {
   			throw new DrizzleValidatorsError(
   				"refineSchema errorMap must be a plain object mapping field names to error messages.",
   			);
   		}
   		for (const [key, errorConfig] of Object.entries(errorMap)) {
   			if (errorConfig === undefined) continue;
   			const targetField = nextShape[key];
   			if (!targetField) {
   				throw new DrizzleValidatorsError(
   					`Cannot set error on unknown schema field "${key}".`,
   				);
   			}
   			nextShape[key] = setErrorOnField(
   				targetField,
   				errorConfig as FieldErrorInput,
   				true, // preserveInline = true so callback inline errors win
   			);
   		}
   	}

   	return rebuildZodObject(baseSchema, nextShape);
   }
   ```

## 6. Test Matrix (`tests/refine-error-map.test.ts`)

Create `tests/refine-error-map.test.ts` to verify all edge cases:

1. **2-Argument Form (`refineSchema(schema, errorMap)`):**
   * String catch-all (`name: "Invalid name"`) overrides `required`, `invalid_type`, and check errors on `name`.
   * Granular object (`email: { required, null, invalid_type, max }`) dispatches the exact string for `undefined`, `null`, `123`, and `"x".repeat(256)`.
   * Dynamic error function (`min: (issue) => ...`) receives the Zod issue and returns the formatted string.
   * Untouched fields keep their default Zod 4 error messages.
2. **3-Argument Form (`refineSchema(schema, callback, errorMap)`):**
   * `callback` replaces `email` with `fields.email.as(z.email())`, and `errorMap.email` styles both `required` ("Email is required"), `email` / `format` ("Invalid email"), and the inherited Drizzle `.max(255)` check ("Too long").
   * `callback` adds a brand-new field (`confirmPassword: z.string().min(8)`), and `errorMap.confirmPassword` styles both `required` and `min`.
3. **Inline Precedence Over `errorMap`:**
   * `callback` sets `age: fields.age.min(18, { error: "Inline 18+" })` and `errorMap` sets `age: { required: "Age required", min: "Map 18+" }`.
   * Passing `{ age: undefined }` outputs `"Age required"` (from `errorMap`).
   * Passing `{ age: 16 }` outputs `"Inline 18+"` (inline check error wins over `errorMap.age.min`).
